# Calibration 正文精简与触发诊断

日期：2026-09-20。状态：三份正文已采用；入口及路由维持原版。

本轮落实 `principles.md`、`discipline/verification.md` 和
`discipline/debugging.md` 的精简，然后完成 16 轮局部因子试验。全部产物验收通过。
W04 的额外加载集中在 calibration 短描述条件；A02 对仓库总览读取规则也敏感。
这些结果支持保留原入口的排除边界，尚不支持把某一句话认定为唯一原因。

## 采用范围与前序证据

模型试验中的三份正文共 7,808 → 5,507 bytes，减少 29.5%。交付检查发现两项
既有契约断言依赖原措辞，随后补回 principles 中的关键短语，共增加 96 bytes。
最终交付为 5,603 bytes，比基线减少 28.2%；未修改或削弱测试。配置默认值和项目知识章节保持
原样；兼容性、最终产物验证、外部状态回读和未验证边界继续保留。调试允许已有
具体故障记录支持修改，不强制为流程重新制造一次失败；最终验证仍然必要。
见[采用决定](../../docs/decisions/2026-09-20-calibration-body-compression-and-routing.md)。

此前七文件候选对照为 8 案例 × 2 版本 × 2 重复，共 32 轮：

| --- | ---: | ---: |
| 独立产物验收 | 16/16 | 16/16 |

正文逐项收益、整包提速和大型项目表现均未得到证明。

## 本轮条件

- 基线提交：`15135fbd5d3e70edbb79d5293beeaa0687e4df23`。
- 请求模型 `gpt-6-astra`，effort `medium`，CLI `0.154.0`。
- 所有组使用同一套正文：原版入口正文加当时冻结的三份精简引用正文。
- W04 为 calibration 描述 × writing-code-docs 描述的 2 × 2 试验。
- A02 为 calibration 描述 × 仓库总览读取规则的 2 × 2 试验；
  writing-code-docs 保持原描述。
- 每格重复两次，共 16 次新上下文执行，四路并发，执行顺序种子 20260920。
  该种子只控制调度顺序；模型采样种子未固定。
- 每轮独立工作区和 Codex home；技能只读、修改路径白名单、命令网络隔离；
  认证对命令不可读，应用、插件、子代理、记忆、目标与 shell snapshot 禁用。
- 复用前次已验证的私有 adapter 和冻结系统技能。仓库 runner 和独立产物
  验收器保持一致。无模型失败、超时或替换重试，16 次全部计入结果。

两个描述候选及总览规则的完整差异见
[tested-factors.diff](tested-factors.diff)。短 calibration 描述删掉了原版的
ordinary-local 排除句，同时压缩了其他措辞。因此本轮检验的是这版描述的整体
影响，没有单独隔离排除句的作用。原版与短描述各组的 SKILL 正文完全一致。

主指标是实际命令返回了技能正文的首次读取，不能用模型声称“使用某技能”代替。
收集器匹配路径及返回正文前缀，随后独立只读复核全部 16 条轨迹；未发现漏读。
这衡量入口读取，不表示每次都完整执行了所有路由。一次 A02 只读入口、未继续
读取基线引用。功能验收和读取计数均无主观偏好打分；本轮未新增盲评优胜排名。

## W04：calibration 描述是主要候选因素

任务是修复 slug 规范化，保持公开函数签名兼容。仓库已有 `make check`，覆盖
回归行为和精确 docstring 合同。所有组均通过 2/2。

| calibration 描述 | writing-code-docs 描述 | calibration 读取 | writing-code-docs 读取 |
| --- | --- | ---: | ---: |
| 原版 | 原版 | 0/2 | 2/2 |
| 原版 | 短版 | 0/2 | 2/2 |
| 短版 | 原版 | 2/2 | 2/2 |
| 短版 | 短版 | 2/2 | 2/2 |

保持 calibration 原描述时共 0/4 次读取，换成短描述后为 4/4。两个重复中，
writing-code-docs 描述长短均未改变这个模式。该结果比前次混合改动更直接地
指向 calibration 入口描述。原版明确排除有清晰仓库规则和可执行反馈的局部工作；
短版省掉了该边界，留下公开合同、兼容性及 harness 等较宽的触发词。

轨迹中四次加载都发生在已看到源码、测试和 docstring 合同之后：三次在首次
测试执行之前，一次在失败之后。某次引用读取与测试并发，但入口读取已先完成。
测试失败无法统一解释四次初始选择。writing-code-docs 正文也没有在这些首次
选择前先行加载；其元数据的可能影响由交叉条件检查。

短描述组随后读取更多通用引用，有三次还加载 `docs_index.md`。本例已有精确
仓库合同，额外通用路由未带来可见的产物收益。作为次要描述指标，短描述四次
累计 token 为 508,296，原描述为 358,071，增加约 42%；该值含缓存上下文，
不能换算为同幅度账单增长或推广到其他任务。

这支持优先保留 ordinary-local 排除边界。公开签名兼容措辞与较宽触发词可能
共同影响选择，但该任务措辞和全局规则没有被消融，作用大小仍未知。

## A02：仓库指令存在额外影响

任务要求按照 installer contract 和 approved adoption decision 修正配置，
并保留扩展字段。各组均通过 2/2，全部读取了 README、文档索引和采用决定。

| calibration 描述 | 仓库总览读取规则 | calibration 读取 |
| --- | --- | ---: |
| 原版 | 原版：直接要求读取总览 | 0/2 |
| 短版 | 原版：直接要求读取总览 | 0/2 |
| 原版 | 条件式：合同决定或相关既有决定时读取 | 1/2 |
| 短版 | 条件式：合同决定或相关既有决定时读取 | 2/2 |

原规则共 0/4，条件式规则共 3/4。短描述单独出现时仍为 0/2，因此不能用
“描述缩短必然增加调用”解释这个案例。条件式指令与描述的组合、语义提示和
模型波动都仍可能参与；每格两次无法可靠分解交互强度。

条件式加短描述的两次都先读 calibration，再读总览；原描述下触发的那一次
在同一命令中先读总览，再读 calibration。仓库 AGENTS 也是启动指令来源，
首次显式 `cat AGENTS.md` 不代表此前不可见。条件式规则并未在本例减少必读
文档，也没有稳定的耗时收益。

A02 明确涉及安装契约和采用决定，语义与现行 calibration 触发规则相符。
这里的额外调用应作为路由敏感性记录，不能仅凭次数判作误触发。

## 判断与后续范围

1. 继续采用本轮三份正文精简。正文在首次选中入口后才读取，当前轨迹没有
   显示它们导致了初始选择；本轮也没有重新比较长、短正文的独立效率。
2. 保留原 calibration 描述中的局部任务排除边界。以后若压缩入口，明确
   区分需要判断合同变更的任务与依照明确合同保持兼容的局部修复。该新措辞
   尚未实现或测试，不把本轮结果冒充它的验收。
3. writing-code-docs 描述压缩在本例没有改变额外触发，不作为优先修复点。
4. 保持仓库总览规则原样；条件式版本未显示阅读减少，A02 的路由还有变化。
5. 保持全局规则原样。它与公开合同等入口语义有重叠，但本轮固定了全局规则，
   无法估计删除或改写它的效果。

这些是小型合成案例的诊断结果。每格仅两次，未覆盖生产大仓库、所有公开 API
任务或其他模型；不能证明统计等价、普遍因果关系或通用性能收益。`rg` 缺失与
Python 路径警告仍是共享环境限制，不能当作技能效果。请求模型与参数有记录，
服务端模型权重身份没有独立证明。
