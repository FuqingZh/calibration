Transaction diagnosis · Lesson 2 · 3 minutes

The missing COMMIT reply

You already know what a confirmed rollback means. Now diagnose the harder case: the database's answer never reaches the service.

The incident

  1. The service starts a transaction.
  2. It inserts a payment with request_id = 'rq-42'.
  3. It sends COMMIT.
  4. The connection drops before the client receives the reply.

The Python client raises a connection error. Nobody has checked the database yet.

Your diagnosis

What can you conclude from the timeout alone?

The rule to keep

Known rollback: retrying cannot duplicate that transaction. Missing COMMIT reply: treat the outcome as unknown, then reconcile by a stable request key before retrying.

PostgreSQL's SQLSTATE catalog names this class 08007 transaction_resolution_unknown. Its COMMIT reference explains what a completed commit guarantees; the error-code appendix is the primary reference for the unknown-resolution condition.
