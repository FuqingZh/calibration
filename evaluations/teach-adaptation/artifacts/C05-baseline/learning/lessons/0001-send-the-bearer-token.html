Authentication API · Lesson 1 · About 3 minutes

Send the Bearer token

Your one win: put the current credential in the right place.

The supported mechanism is a short-lived access token in the HTTP Authorization header, using the Bearer scheme.

The shape to remember is:

Authorization: Bearer <access-token>

So a small client request starts like this:

GET /widgets HTTP/1.1
Host: api.example
Authorization: Bearer eyJ…

Do not put a static key in the URL query string. That older mechanism was removed in API version 3.0. This course follows the project's current v3.2 contract, not the older blog that was previously saved. Read the primary source.

Retrieval check

Without looking back, which request uses the currently supported transport?

Request A

GET /widgets?api_key=abc123 HTTP/1.1

Request B

GET /widgets HTTP/1.1
Authorization: Bearer abc123
Reveal feedback

Request B. The credential travels in Authorization: Bearer …. Request A uses the removed static query-string API-key mechanism.

Make it stick

Close this page and say the header aloud once: “Authorization, Bearer, access token.” Then adapt that one header in your client when you are ready.
