# Acme Parser 4.2 Empty-Tag Compatibility

Status: current  
Verified: 2026-08-12  
Applies to: Acme Parser 4.2

## Boundary and expected contract

This record applies to XML supplied to Acme Parser 4.2 when a caller must
distinguish a missing field from a present field whose value is an empty
string.

## Verified behavior

The behavior was reproduced in fixtures A, B, and C:

- `<tag/>` produces a missing field.
- `<tag></tag>` preserves the field with an empty-string value.

The fixture record did not capture the operating system or additional parser
configuration, so behavior outside the verified parser version and fixture
environment remains unverified.

## Failure signature

A field intended to contain an empty string is absent after parsing when the
input uses the self-closing form `<tag/>`.

## Safe adaptation

For inputs consumed by Acme Parser 4.2, emit an explicit opening and closing
tag (`<tag></tag>`) whenever the parsed result must retain an empty string.
Do not use `<tag/>` for that contract.

## Reproduction check

Parse two otherwise equivalent inputs with Acme Parser 4.2, one containing
`<tag/>` and one containing `<tag></tag>`. Confirm that the first result omits
the field and the second contains the field with an empty-string value.

## Review conditions

Re-run the reproduction check before applying this record to another parser
version or materially different parser configuration. The maintainers of the
integration that invokes Acme Parser own that follow-up. Supersede this record
if a later verified version changes the behavior.
