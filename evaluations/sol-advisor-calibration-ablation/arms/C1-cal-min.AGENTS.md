# Global AGENTS.md — CAL-MIN candidate

Use `$calibration` once before substantive cross-project engineering judgment,
non-local architecture or refactoring, compatibility-sensitive public
contracts, unclear validation, repository harness changes, agent or workflow
evaluation, or durable engineering documentation. Ordinary local work with
clear repository rules and executable feedback proceeds directly from those
sources. Load only references routed for the current task.

For repository changes, select validation proportionally to affected behavior
and contracts. Run the smallest repository-owned checks that decide the changed
surface; use the complete gate only when runtime behavior, generated artifacts,
executable workflows, compatibility, or repository policy requires it. Report
an unavailable required check and its residual risk.

Keep discovery and mutations inside the assigned workspace. Treat sandbox-only
host observations as hypotheses and bound any necessary remote, shared, or
parent-root search before traversing it.

## Route once

At the first substantive decision, freeze a short capsule with exactly:
`Authority`, `Frozen boundary`, `Compatibility`, `Validation`, and
`Reopen only if`. Then exit cross-project routing and return to the
repository-local executable feedback loop. After context compaction, restore
the capsule instead of repeating discovery or making the same decision again.
Reopen it only when a named condition occurs or new evidence changes the
contract.

When work first proposes a new public artifact, schema, CLI, WDL, or consumer,
make one explicit scope-increment decision against the frozen boundary. Keep or
reject that increment once; do not reopen it without new contract evidence.

## AO safety kernel

- Preserve one writer for every repository, branch, and worktree.
- A controller never edits, stages, commits, or pushes an AO owner's sibling
  worktree.
- Perform one authoritative AO owner check only when existing ownership or an
  authorized PR-continuation route makes it relevant. Owner absence alone does
  not prove that every possible writer is quiesced.
- Load the on-demand AO runbook before detailed spawn, claim, handoff,
  restoration, transfer, or teardown work. Ordinary clean, exclusive, unowned
  local work remains in its assigned checkout; dirty or parallel unowned work
  may require isolation; AO-owned work routes to its owner.

Preserve owned state when authoritative host context, continuation proof, or a
safe route is unavailable. Never infer runtime release merely from a missing
terminal or session; teardown requires an empty OS-owned containment boundary.

## Progress and feedback

Emit progress commentary only when ownership is resolved, the first failing
evidence is available, a patch is ready, validation finishes, or a real blocker
requires authority. Same-scope mechanical feedback stays in the current writer
loop. Reopen calibration only when feedback changes the authorized contract or
the distinct review-convergence budget is exhausted.

Use `github:gh-address-comments` for actionable pull-request feedback and
`github:gh-fix-ci` for failing GitHub Actions when their triggers apply. These
skills do not grant write authority or transfer AO ownership.

For explicit AO installation or host-operation tasks only, load the rendered
private host authority if available, then the portable AO runbook. Do not load
either for ordinary repository work and do not treat sandbox-visible absence as
proof that host authority is absent.
