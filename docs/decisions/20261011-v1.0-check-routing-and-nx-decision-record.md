# Check Routing And Nx Assessment

Date: 2026-10-11
Status: assessed; Nx not adopted

## Decision

Keep PDM as the repository-owned validation entrypoint. Select its existing
tasks by the affected contract, while retaining `pdm run check` as the complete
CI gate. This cleanup changes documentation navigation and lifecycle labels;
it does not introduce automatic check skipping, caching, or new CI policy.

## Repository Evidence

`pyproject.toml` already defines separate Python, Markdown, shell, test, link,
and skill checks, composed into one full gate. `pdm.lock` owns their dependency
versions. The repository has one validation environment and one CI job, without
a root Node package or an Nx project graph.

Directory boundaries do not determine validation dependencies. For example:

- Skill validation reads invocation metadata, references, and installer arrays.
- Markdown link validation can fail when a linked file is removed, even if the
  linking document is unchanged.
- Repository contract tests read documentation, skills, and installer policy.
- Executor integration checks depend on Codex, bwrap, and runtime isolation.

## Options

| Option | Benefit | Additional obligation |
| --- | --- | --- |
| Existing PDM tasks | Focused local checks with the same underlying tools as CI | Select the affected seam explicitly; report omitted boundaries. |
| Named PDM composites | Shorter commands for recurring groups | Add only after repeated use establishes a stable group; preserve the full gate. |
| Nx targets, affected selection, and caching | Dependency-aware scheduling and reusable deterministic results | Add Node tooling, Nx configuration, input/output definitions, and dependency edges; validate them against representative changes. |

[Nx can be added to a single existing project](https://nx.dev/docs/kb/adding-to-existing-project).
Its value does not depend solely on being a monorepo. However,
[affected selection](https://nx.dev/docs/features/ci-features/affected) depends
on project or task inputs and dependencies; missing inputs can omit needed
checks. Its documented lockfile dependency analysis does not list `pdm.lock`,
so this repository would need an explicit input for that dependency authority.

[Cache inputs](https://nx.dev/docs/kb/configure-inputs) must cover applicable
runtime versions as well as source files. Live external-state and isolation
checks would need separate treatment from deterministic text checks. These
are additional contracts that an Nx wrapper cannot infer from our directories.

## Assessment And Reopening

Existing PDM tasks cover the requested focused validation. No timing study or
Nx prototype in this cleanup establishes a scheduling or caching benefit;
there is no measured break-even case for adding another toolchain. Retain the
current entrypoint and defer both Nx and an automatic path selector.

Reopen when repeated CI timing identifies substantial avoidable execution,
or independently maintained projects need a shared dependency graph. A bounded
trial must compare total setup and execution time, demonstrate invalidation for
source, linked-file deletion, installer, lockfile, and runtime changes, and keep
live checks fresh. Changing the full gate or coverage obligations is a separate
decision.
