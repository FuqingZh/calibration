# Self-Contained First-Party Skills Migration Implementation Plan

**Date:** 2026-08-26

**Status:** Implemented

**Owner:** calibration repository

**Base:** `d5225c15dac2d47e60cd57104ac56fa84fb12b87`

## Outcome

Make every installed first-party skill independently portable. Every active
local file dependency reachable from a first-party `SKILL.md` must live inside
that skill's own directory and remain readable when the skill directory is
copied without the repository around it. Preserve the installer's existing
skill-directory symlink model so lexical paths below an installed
`<CODEX_HOME>/skills/<skill>/` work without resolving the symlink first.

## Current State And Problem

`skills/calibration/SKILL.md` currently escapes its skill root to load the
top-level `references/engineering/` tree and the AO continuation runbook under
`docs/runbooks/`. `skills/retrospect/SKILL.md` similarly names two files owned
by the calibration documentation tree. Those references work in a source
checkout but are not a closed skill package and can fail when a skill is
copied independently or traversed through an installed lexical symlink.

The validator currently resolves a reference relative to its source and then
falls back to the repository root. That fallback can make an escaping or
incorrect reference appear valid. The writable evaluation runner compensates
for the same source layout by copying repository-level references and the AO
runbook into its temporary Codex home.

Git history shows that older decisions and plans accurately record the former
top-level paths as the layout that existed when those records were written.
Those historical statements are not migration targets unless they are active
navigation, live Markdown links, fixtures, executable expectations, or claims
about current authority.

## Frozen Design

1. Move the contents of `references/engineering/` to
   `skills/calibration/references/`, flattening the redundant `engineering`
   level. The resulting root contains `principles.md`, `naming/`,
   `discipline/`, `design/`, `docs_index.md`, and `docs/`.
2. Move the AO continuation runbook to
   `skills/calibration/references/agent-orchestrator-review-continuation.md`.
3. Change calibration routing to use only `references/...` paths below its own
   skill root.
4. Give `retrospect` authoritative local copies of the trace-retro document
   contract and task-traces workflow guidance, update their internal link, and
   route retrospective work from calibration to `$retrospect` rather than
   reading those files across skill roots.
5. Remove the former top-level reference tree and runbook path. Do not retain
   symlinks, mirrors, or compatibility copies.
6. Remove the writable evaluation runner's obsolete repository-level runtime
   closure copies while retaining unrelated third-party license closure.

## Compatibility And Documentation Decision

This is an intentional one-step internal source-layout migration. There is no
old-path compatibility layer: no compatibility symlink, duplicate mirror,
repository-root fallback, or parallel canonical path will remain. Consumers
of current source paths must move to the owning skill-local path in the same
change. Old commits remain the compatibility mechanism for historical
checkout and audit. Historical prose that truthfully describes its then-current
layout remains unchanged; active authority/navigation and real links are
updated to the new canonical paths.

Invocation metadata for `calibration` and `retrospect` remains unchanged
because ownership and invocation behavior do not change. Installation remains
directory-symlink based. The compatibility risk is limited to external tools
or untracked documentation that directly address the removed repository paths;
they must adopt the new skill-local paths.

## Implementation

### 1. Move Canonical Content And Rewire Routing

- Move the engineering reference tree and AO runbook into calibration's
  `references/` directory.
- Move the two retrospect-owned documents into
  `skills/retrospect/references/`, with exactly one authoritative copy each.
- Update relative links within moved documents for their new owners.
- Update calibration's document router to direct retrospective work to
  `$retrospect` and remove cross-skill file dependencies.
- Update `AGENTS.md`, `README.md`, and `docs/README.md` to describe skills as
  self-contained source packages and point current authority to the new paths.

### 2. Enforce Skill-Root Closure

- Change `scripts/validate_skills.py` so a local dependency reachable from an
  active first-party skill resolves relative to the referencing file and is
  rejected unless it exists inside the owning skill root.
- Do not treat URLs, fragments, or explicit `$skill`/skill-name routing as file
  dependencies.
- Do not allow a repository-root fallback to hide a missing or escaping path.
- Continue validating vendored skills according to their existing repository
  contract without accidentally classifying routing text as local files.
- Add negative controls where an escaping target exists elsewhere in the
  repository and where lexical traversal through a skill symlink would fail
  under the former layout.

### 3. Prove Independent Portability And Runtime Compatibility

- Install both `standard` and `ao-worker` profiles into disposable Codex homes.
- Traverse calibration references from the lexical installed
  `<home>/skills/calibration/SKILL.md` path, without `realpath`, and assert that
  every routed local file is readable and lexically contained by the installed
  calibration skill directory.
- Copy each first-party skill independently to a temporary root and validate it
  without repository context.
- Preserve and exercise installer behavior for source links, owned-link
  migration, and foreign-target preservation.
- Update routing, Markdown-link, and writable-evaluation tests to use the new
  canonical ownership and prove the runner no longer needs repository-level
  reference closure.

### 4. Remove Stale Current Paths

- Update scripts, tests, fixtures, current authority maps, and live Markdown
  links that address the removed paths.
- Inspect each remaining old-path mention. Retain it only when it accurately
  records then-current history and is not executable navigation or a live
  current-authority claim.
- Verify that the removed top-level directories do not remain as symlinks,
  mirrors, or generated artifacts.
