# Review-Convergence Routing Implementation Plan

Version: v2.3
Date: 2026-08-03
Status: completed bounded maintenance increment; no behavioral-improvement claim

## Goal

Clarify the portable review-convergence contract so an owning worker continues
same-scope mechanical feedback, but preserves delivery state and recalibrates
PR routing when exact-current-head review expands the current explicitly
declared and authorized contract or the distinct configured
review-convergence budget is exhausted.

## Scope And Non-Goals

This increment changes the repository harness reference, generated global
agent instructions, calibration behavioral prompts, and narrow structural and
installer-propagation tests. The routing decision is among one PR, independent
PRs, or a dependent stack. Out-of-contract feedback is rejected or escalated
unless an authorized contract expansion is accepted first. Independent slices
remain independent; genuinely dependent slices use platform-native stacking
when available and ordinary dependent PRs otherwise. Transport, polling, and
idempotent-operation retry exhaustion remains on its preserve-and-report path.

It adds no universal size or review-round thresholds, affected-surface
framework, scheduler, tool, AO or GitHub integration, metrics, database, or
workflow-improvement claim. It does not vendor `addyosmani/agent-skills`,
install `gh-stack`, or change AO project `autoMerge`.

## Implementation Slice

1. Update `references/engineering/discipline/harness.md` with the compact
   convergence rule and thin DORA Small Batches and Google Small CLs links.
2. Update `codex/AGENTS.md.template` with the matching global tripwire.
3. Add two cases to `skills/calibration/test-prompts.json` covering same-scope
   continuation and cross-contract or exhausted-budget recalibration.
4. Add narrow repository tests for the rule, external links, prompt behavior,
   forbidden thresholds and tools, and propagation into installed
   `AGENTS.md`.

The slice has no predecessor and remains one review unit because the prompt and
generated-instruction behavior depend on the reference contract they encode.

## Compatibility, Risk, And Rollback

This is a documentation and behavioral-routing clarification with no runtime
API or installer-interface change. The main risk is contradictory or overly
prescriptive wording; structural tests constrain the shared phrases and
non-goals. Rollback is a normal revert of this single semantic increment.

## Delivery

Commit as one focused change, open one ready pull request, and continue only
same-scope mechanical CI and exact-current-head review fixes. If review expands
the current explicitly declared and authorized contract or the distinct
configured review-convergence budget is exhausted, preserve branch, head,
worktree, owner, and feedback state and stop remote review for a new calibration
decision. Review feedback cannot authorize a contract expansion by itself.
