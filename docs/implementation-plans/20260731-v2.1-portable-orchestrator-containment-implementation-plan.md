# Portable Orchestrator Containment Implementation Plan

Version: v2.1
Date: 2026-07-31
Status: CAL-1 public contract delivered; no behavioral-improvement claim

## Scope

This next-round increment implements only CAL-1:

- add the portable assigned-workspace containment invariant;
- bound recursive discovery on remote, network, and large shared filesystems;
- require an empty OS-owned containment boundary before treating termination
  as complete or reporting runtime release, while allowing a terminated state
  with incomplete cleanup kept observable and retryable;
- conditionally route explicit host-operation work to rendered private
  authority;
- document that per-worker systemd containment is proposed upstream, not
  current AO behavior; and
- add structural and behavioral contract coverage.

It does not modify private host authority, AO source or deployed services,
installer or adoption behavior, repository permissions, or AO project
`autoMerge`.

## Completion

- Portable harness invariant: complete.
- Generated global-agent search and host-authority guidance: complete.
- Public AO guide and durable decision: complete.
- Process-release contract and focused structural assertions: complete.
- Shared-aggregation-root prompt artifact: present but unevaluated; it is not
  behavioral evidence and supports no compliance or improvement claim.
- Structural, portability, focused, and canonical repository validation:

CAL-1 delivery is limited to the public contract and its static validation. No
model evaluation is part of this plan.

## Conditional Future Reopening

A behavior evaluation is not an active phase. It may reopen only under a
separately reviewed executable protocol. That protocol must:

- create a temporary aggregation root, initialize the assigned repository
  itself as the Git root, and create the synthetic sibling beside that
  repository through explicit case setup;
- keep fixture-local `AGENTS.md` limited to repository verification, while the
  task prompt supplies neither the containment rule nor a direct config path;
- record structured command and tool events, resolve every search root, and
  reject traversal whose resolved root escapes the assigned repository;
- hash a separate sibling manifest before and after the run to prove no
  mutation; and
- require a task write plus repository verification so a read-only answer
  cannot pass.

Before execution, that separate protocol must freeze the candidate source,
model, reasoning effort, Codex CLI version, repetition count, scoring method,
commands, and private evidence location. Add a baseline or repeated blind
comparison only when the separately reviewed claim and expected model variance
require it.

## Upstream Follow-Up

Per-worker systemd scopes remain an upstream AO proposal. They are not an
unimplemented calibration phase and must not be described as active
containment until upstream AO implements the behavior and representative
runtime evidence verifies it.
