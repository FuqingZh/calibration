# v1.7 AO Repository Adoption Contract — Historical Summary

Status: historical public summary.

This plan established that AO repository adoption has four distinct evidence
states: `registered`, `configured`, `runtime-ready`, and
`continuation-proven`. Static configuration or health checks cannot establish
continuation; that requires a real pull-request feedback event returning to the
owning worker, followed by a verified correction.

The delivered repository adapter plans, applies, and reads back adoption for one
explicitly selected repository on its supported profile. It does not bulk-enroll
repositories, grant permissions, make AO a public dependency, or enable
automatic merge behavior.

The durable contract now lives in:

- `../../references/engineering/discipline/harness.md`;
- `../runbooks/agent-orchestrator-review-continuation.md`;
- `../decisions/2026-07-23-ao-review-continuation-adoption.md`;
- `../decisions/2026-07-29-ao-native-delivery-convergence.md`; and
- `../../scripts/adopt_ao_repository.py`.

The original implementation and bounded continuation canary were delivered
through pull requests #20 and #21, establishing `continuation-proven` for
calibration without extending that result to other repositories. Current-host
service configuration, session identifiers, run identifiers, commit hashes,
diagnostics, and rollback material are intentionally excluded from this
portable historical record.
