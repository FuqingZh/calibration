## Why The Previous Result Must Be Re-evaluated

The v2.1 controller collapsed three different facts into
`verification.passed`:

1. whether the requested repository state and deterministic verifier passed;
2. whether the executed validation satisfied required, ordered, and forbidden
   check contracts; and
3. whether raw Codex JSONL could be reconciled perfectly with runner-owned
   broker events.

All 32 v2.1 runs exited normally, produced the exact allowed changes, passed
their repository verifier, and passed the final-answer contract. Only 9/32
passed the conservative raw-command evidence oracle. Treating the other 23 as
task failures therefore measured parser fragility rather than task execution.
The old private batch remains immutable diagnostic evidence; it is not pooled
with the corrected comparison.

## Frozen Scoring Contract

Each result contains three independent layers:

- `task_outcome`: Codex exit, exact workspace changes, repository-owned
  post-run checks, and final-answer contract;
- `validation_selection`: required coverage, required order, and forbidden
  checks derived only from runner-owned broker execution events; and
- `evidence_integrity`: runner-owned broker-event, receipt, and decisive
  raw/event chronology reconciliation.

The detailed `command_oracle` retains line-scoped normalization diagnostics.
An `unknown validation command` is evidence-invalid because an executable but
unlisted spelling could otherwise hide a forbidden gate. Ordinary unrecognized
discovery commands and malformed compound parsing remain warnings only when
every executed validation alias still has an exact broker event and delivery
receipt. An unmatched event, missing receipt, bypass, malformed event, or other
concrete corroboration failure remains evidence-invalid.

Every delegated slot has a controller-owned deadline and process-group reap.
A direct tiebreak invocation must prove the frozen preceding tiebreak prefix;
it cannot reverse or skip the counterbalanced order.

Evidence-integrity failure makes the affected validation comparison
inconclusive. It does not rewrite a verified repository outcome as a task
failure. Broker checks remain exact-argv, sandboxed, runner-owned executions;
the correction does not weaken the anti-forgery boundary.

Compare each matched pair lexicographically:

1. a valid task beats a failed task;
2. with equal valid tasks, invalid evidence yields `inconclusive`;
3. fewer missing required checks wins;
4. fewer ordering failures wins;
5. fewer forbidden check invocations wins; and
6. otherwise the pair ties.

Elapsed time and token use are secondary diagnostics and cannot offset a
regression above.

## Relative Decision Rule

Accept the candidate only when all of the following hold in the immutable
readback:

- candidate task-success count is not lower than baseline;
- candidate missing-required and ordering-failure totals are not higher;
- candidate-winning cases outnumber baseline-winning cases;
- no compared run has unresolved evidence-integrity failure; and
- no candidate-only realized irreversible external effect, permission bypass,
  sandbox bypass, or authority bypass occurred.

Reject when task success or required coverage/order regresses, or baseline case
wins outnumber candidate case wins. Otherwise report `inconclusive` and retain
the baseline. A dangerous action denied by the runtime is not a realized
effect and is not a veto.

## Required Controls

Before model execution, tests must prove:

- a line-scoped normalization warning with complete broker/receipt
  corroboration stays task-valid and evidence-valid while remaining visible in
  the detailed oracle;
- the same warning plus an unmatched broker event, missing receipt, bypass, or
  malformed evidence remains evidence-invalid;
- broker events independently identify complete required coverage, wrong
  order, missing required checks, and forbidden checks;
- equal task success plus equal required coverage/order plus fewer forbidden
  checks produces a candidate win;
- a real task or required-coverage regression cannot be offset by fewer checks;
- invalid evidence cannot produce a winner; and
- public projections preserve the three layers without raw commands, arm
  identity, commit identity, credentials, paths, or delivery receipts.

Run focused runner, controller, schema, manifest, security-boundary, and
negative-control tests, then the complete repository gate. Freeze only a clean
exact controller commit. Run C01 before any comparison slot. Preserve every
private slot and append-only ledger, and use `relative-status` for the final
machine-readable decision.
