# Trace Retro

## Use When

Use this type for task-level retrospectives that record expectation versus
actual outcome, judgment errors, validation quality, and rules to carry
forward.

## Method Reference

Use the [task traces and retrospectives guidance](../workflow/task_traces_and_retros/20260527-v1.0-task-traces-and-retros.md)
for scope, evidence handling, and promotion rules.

## Local Requirements

- Place it in project `.traces/retros/` unless repository-local trace rules say
  otherwise.
- Record the expected goal, risk, validation plan, and key assumptions.
- Record actual changes, validation, and result.
- Explain the delta between expected and actual.
- State a rule to carry forward and whether the learning should be promoted to
  project docs, repository-local instructions, or calibration.
- Preserve the judgment signal, not raw command logs or a long conversation
  transcript.
- Promote stable project rules out of the trace and into their owning durable
  document type.

## Complete When

The next similar task can start with a better assumption, validation path, or
rule than the original task had.
